How the project was built

Workflow

Seven steps, in the order they were done. Each step's output feeds the next one, and the app and the simulation share one data format so the same analysis code runs on both.

    Audit the prototype

    Two tables: a summary row per participant and a row per transition. The app's exports and the simulated files use the same columns.

    Simulate 2,000 participants aged 55–89 in R

    Demographics, cognitive status at Taiwan's age-specific rates, completion times calibrated to Tombaugh (2004), errors, and 24 inter-node RTs per part built from the same layout algorithm as the app.

Step 1 → 2

What changed from the prototype

The prototype looked finished but produced data that could not be used. These are the problems found and how the new version handles them.

Step 3

Two files, one format

The same two tables come out of the app and the simulation. They differ in what one row means.

participants · one row per person

2,000 rows · wide format

  • Demographics: age, sex, education_years, device, and group (simulation only)
  • For A and B: time_s, errors, init_ms, mean_rt_ms, rt_sd_ms, rt_cv, interrupted
  • Derived: B_minus_A_s, B_div_A

Use for classic TMT analysis: group comparisons, regression, norms.

transitions · one row per segment

96,000 rows · long format

  • part, transition_index (1–24), from_node → to_node
  • distance_norm: distance between the two circles as a share of the board diagonal
  • rt_ms: time for that segment; errors: wrong taps during it

Use for process analysis: switch costs, distance effects, multilevel models.

A_time_s     = (A_init_ms + sum(rt_ms)) / 1000      # per person, Part A
A_mean_rt_ms = mean(rt_ms)   A_rt_sd_ms = sd(rt_ms)   A_rt_cv = sd / mean
A_errors     = sum(errors) + errors made before circle 1

The transitions file can rebuild every RT summary in the participants file; the reverse is not possible. Join them on participant_id.

Step 4

How the simulation works

Base R only, seed 20261024, about three seconds to run. Each participant gets a latent completion time; the time is then split across 24 transitions.

Person level

  • Age 55–89 uniform; sex 53% F; education falls with age (cohort effect).
  • MCI and dementia (all-cause, labelled Dementia) follow Taiwan's age-specific rates (Sun et al., 2014; ages 55–64 extrapolated), lower for people with more education than their age peers.
  • log(time) = intercept + age + age² − education + MCI + Dementia + shared speed factor. Age curves are fitted to Tombaugh (2004) Table 2 for ages 55–89.
  • Errors: Poisson, calibrated to Ashendorf (2008). Part A errors do not differ by group; Part B errors rise in MCI and Dementia. Each error adds about 1.4 s.

Transition level

  • A fresh random layout per part with the app's own algorithm, so distances are realistic.
  • Each segment's weight = distance × remaining distractors (Part A only) × log-normal noise (larger with age and impairment) × occasional lapses (1.8–3.5×).
  • Part B: number→letter segments cost more, rising for later letters.
  • Weights are scaled so the segments sum to the person's completion time.

Step 7

Item response theory: A and B

Each part's 24 transitions are the items. Random layouts mean "transition 7" joins different circles for different people, so the distance effect is removed first. On simulated data these results mostly show the code works; the test's real psychometrics need real data from about 500 or more people.

Times are continuous

Which IRT checks continuous times need

A single total time per part cannot be analysed with IRT, because IRT needs several items. The 24 transition times make it possible. They are continuous, positive and right-skewed, so the standard model is the lognormal response-time model (van der Linden, 2006). Samejima's continuous response model is meant for bounded rating scales, not times. Binning times into categories for a graded response model is a practical second route, but it discards information.

Measurement invariance results

The one-factor lognormal model on log RT, fitted in each group with equality constraints added step by step (lavaan). A step holds when CFI drops by no more than .010 and RMSEA rises by no more than .015 compared with the step before.

Scalar invariance holds for every grouping in both parts, so mean speed can be compared across age, education and device. Strict invariance fails for age because older people's times vary more from one transition to the next. That is the within-person variability this project studies, not test bias, and comparing means does not require it. The simulation contains no group-specific item bias, so these results show the code works; real data, especially phones versus tablets, will be the real test. If scalar invariance fails on real data, the script lists the five constraints that strain the model most.

The method references in this section (van der Linden 2006, 2007; van der Linden & Guo 2008; Samejima 1973; Yen 1984) are standard but were not part of the citation check. The same applies to Cheung & Rensvold (2002) and Chen (2007), the source of the cut-offs used below.

Step 6 · deep search

What the literature says

Five searches: digital versus paper validity, process metrics, design and administration, normative data, and a check of every reference. Full citations are in the research report.

Digital versions are related to paper, not interchangeable

  • Digital and paper completion times correlate about r = .5–.8. Several authors say the versions are not equivalent (Drapeau 2007; Bracken 2019).
  • Drawing on a tablet with finger or stylus stays within about ±10% of paper, and B−A is roughly kept (Björngrim 2019; Lunardini 2020; Fellows 2017).
  • Tapping on a phone changes the pattern. In mindLAMP (25 targets) Part A was slower than paper and Part B faster, so B−A shrank from about 40 s to about 7 s (Shvetz 2021). An iPhone ResearchKit version shows the same compression (Zhou 2025).
  • Only one study compares tap and drag in the same people (Murphy 2026, Parkinson's disease).

Process metrics: promising, not yet proven

  • Time spent inside circles (dwell) is the process feature that most often separates groups (Libon 2024, n = 321; De Anda-Duran 2025).
  • Reported accuracy is modest: AUC .42–.73 in Dahmen 2017, .67 in a 2026 MCI preprint. No study shows process metrics add value beyond total time in a nested test.
  • Within-person RT variability rises with age and in very mild AD (Hultsch 2002; Duchek 2009: CV .28 vs .43), but no study has computed it across TMT transitions. That is an open question this app can answer.
  • Distance drives segment time: r = .49 (A) and .68 (B) (Woods 2015).

Errors

  • Ashendorf 2008 (269 controls, 200 MCI, 57 AD): Part B mean errors .45, 1.05, 1.39; at least one Part B error in 30%, 59% and 72%.
  • Part A errors did not differ between groups.
  • MCI vs controls: Part B time has sensitivity 43%, specificity 91%; errors 59% and 70%.

Norms in Asia

  • No published means and SDs for the classic TMT in Taiwan were found; only a Color Trails norms thesis and a tablet TMT study.
  • Part B is usually adapted: hiragana in Japan (Suzuki 2022; age 70+: A 52.7 s, B 137.4 s), circles and squares in the Chinese Shape Trail Test (Zhao 2013), Korean syllables or shapes (Jang 2016).
  • Taiwan prevalence at 65+ (Sun 2014): MCI 18.8%, dementia 8.0%, rising from 13.9% / 3.4% at 65–69 to 26.2% / 21.9% at 85–89.

What to do next

Limits and next steps

In priority order.

App

  1. Stop counting circles crossed during a swipe as errors; count only lifts or taps on a wrong circle.
  2. Record the input mode (tap or swipe) for each transition, or allow only one mode per study.
  3. Add time caps (150 s A, 300 s B) and store whether a part was stopped.
  4. Keep circles at least 44 px wide; on small phones use fewer circles or require a tablet.
  5. Add a no-crossing rule and a path-length band to the layout generator; save path length per session.
  6. Auto-save each participant on the device so a session is never lost.
  7. Collect app-specific norms: paper norms do not transfer to tapping.

Simulation

Done in this version: ages 55–89; Part B age curve, error rates, A–B correlation and Taiwan impairment rates recalibrated; the Part B late speed-up removed.

  1. Cap Part B at 300 s and report how many hit it: 91 participants exceed 300 s now.
  2. Give A and B separate tap-speed factors so tapping can shrink B−A, and run the analyses under both input modes.
  3. Replace the extrapolated ages 55–64 and the Tombaugh curves with Taiwanese data when they exist; no Taiwanese TMT norms were found.
  4. State whether B/A is a mean of individual ratios or a ratio of means.
Reproduce

How to run

In RStudio, set the working directory to the project folder first. Needs ggplot2, dplyr and mirt; the IRT script also uses lme4 (section 8) and lavaan (section 9).

setwd("D:/99_R/SimulationTailMaking")
source("simulate_tmt_en.R")   # writes tmt_sim_participants.csv and tmt_sim_transitions.csv
source("plot_tmt.R")          # writes figures/*.png
source("irt_tmt.R")           # writes irt_output/*, about 3 minutes

# Real data exported from the app: combine all files, then rerun the plots
p  <- do.call(rbind, lapply(list.files(pattern = "_summary\\.csv$"), read.csv))
tr <- do.call(rbind, lapply(list.files(pattern = "_transitions\\.csv$"), read.csv))

The app needs no build: open tmt_mobile_en.html in a phone browser. The first load needs a connection for the chart library.
